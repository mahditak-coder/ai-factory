# کارخانه تولید نرم‌افزار (v0.3.0 → تثبیت v0.3.1) — `factory.html`

> **v0.4.0:** نوع پروژه جدید `fullstack-python` (اسکفولد خودکار قالب فول‌استک) + دکمه‌های «🧪 اجرای آزمون‌های پروژه» و «📦 نصب وابستگی‌ها» + APIهای `/api/factory/{scaffold,testrun,deps}` و `/api/factory/testrun`. مستندات قالب فول‌استک: `docs/FULLSTACK.md`.

چرخه کامل واقعی: درخواست کاربر ← تحلیل/برنامه‌ریزی ← تأیید ← تولید فایل ← اجرا ← آزمایش ← اصلاح خودکار ← پیش‌نمایش ← خروجی ZIP.

داربست نسخه 0.2.0 (پنل، Workspace، پل OpenCode) دست‌نخورده باقی مانده و v0.3.0 فقط ماژول‌های افزودنی اضافه می‌کند.

## معماری

```
dashboard/factory.html + factory.js   ← رابط کاربری کارخانه (فارسی/RTL، ۷ زبانه)
        │ fetch (بدون کلید)
        ▼
core/server.py  — مسیرهای /api/factory/*  (اعتبارسنجی، حداکثر، نام پروژه)
        │
        ├─ core/factory.py    چرخه حیات پروژه: meta.json، تاریخچه .factory/history.json،
        │                     برنامه‌ریزی و تولید با نشست‌های واقعی OpenCode
        ├─ core/checker.py    بررسی واقعی: ast.parse (پایتون)، node --check (JS)، json، HTML
        ├─ core/runner.py     اجرای امن: تشخیص از «فکت‌های» پروژه، argv ثابت، بدون shell
        └─ core/exporter.py   خروجی ZIP + نسخه پشتیبان + حذف محرمانه‌ها
                │
                ▼
        opencode serve (127.0.0.1:4556) ← مدل رایگان GLM (تولید کد واقعی، نه شبیه‌سازی)
```

## نحوه کار

- **متادیتای پروژه:** `projects/<name>/meta.json` (نوع، توضیح، زمان ایجاد/تغییر).
- **تاریخچه تغییرات:** `projects/<name>/.factory/history.json` — افزونگی‌پذیر (append-only).
- **برنامه‌ریزی:** نشست OpenCode به عنوان «🏭 برنامه …» — خروجی برنامه قابل‌مشاهده؛ کاربر تأیید (`/api/factory/approve`) یا اصلاح می‌کند.
- **تولید:** نشست «🏭 تولید …» با دستورالعمل سخت‌گیرانه فارسی (۷ قانون، از جمله بررسی `index.html` پیش از پایان)؛ فایل‌ها واقعاً در پوشه پروژه نوشته می‌شوند.
- **اجرای امن:** تشخیص نوع فقط از فکت پروژه:
  - `package.json` با `main` → `node`
  - `server.py` / `main.py` / `app.py` → `python`
  - `index.html` → `python -m http.server` (فقط روی 127.0.0.1، پورت از 8610–8658)
  - هیچ shell درگیر نیست؛ متغیرهای `OPENCODE_SERVER_PASSWORD` و امثال آن به فرایند فرزند نمی‌رسند؛ به فرزند `AI_FACTORY_PORT` و `PORT` داده می‌شود.
- **آزمایش:** `checker.check()` خطاها را با kind فهرست می‌کند؛ فایل‌های `.factory` و `__pycache__` هرگز بررسی نمی‌شوند.
- **اصلاح خودکار:** حداکثر `FIX_MAX_ATTEMPTS=3` دور؛ پیش از هر چرخه نسخه پشتیبان Zip در `backups/<project>/` ساخته می‌شود؛ گزارش خطای واقعی به نشست تولید ارسال می‌شود و با `done_since()` پایان پاسخ مدل تشخیص داده می‌شود. هر دور ثبت می‌شود.
- **خروجی ZIP:** تنها مسیرست `exports/`؛ حذف التزامی: `.factory, __pycache__, node_modules, .git, *.pyc, *.log` و محرمانه‌ها (`*.token, *.pem, *.key, .env`). سلامت با `zipfile.testzip()` تأیید می‌شود. کپی به Downloads فقط با مجوز ذخیره‌سازی ترموکس (`termux-setup-storage`).

## مدل امنیتی

- گوش‌دادن فقط `127.0.0.1`؛ هیچ shell و فرمان دلخواه از مرورگر.
- عملیات‌های حساس: حذف پروژه نیازمند `{"confirm": true}` (در غیر این صورت 403)؛ حذف/تغییر نام پروژه در حال اجرا ممنوع (409)؛ پیش از حذف، نسخه پشتیبان اجباری است.
- دانلود ZIP: فقط فایل‌هایی که پدرشان `exports/` است و `name` با `<project>-.zip` آغاز می‌شود.
- توکن OpenCode در هیچ پاسخ HTTP، لاگ، یا ZIP دیده نمی‌شود (تست ۱۳ از مجموعه آزمون کارخانه).

## آزمون پذیرش

```bash
bash scripts/ai-factory-test-factory   # ۲۵ بررسی، همه ۱۴ سناریوی الزامی، شامل تولید و اصلاح با مدل واقعی
```

سناریوها (۱۴ الزامی): ساخت پروژه، ایجاد فایل واقعی، باز کردن پروژه قبلی، حفظ تغییرات، اجرای وب، مشاهده خروجی، تشخیص خطا، اصلاح، تست مجدد، ساخت ZIP، سلامت ZIP، مسیر غیرمجاز، محرمانگی، استقلال دو پروژه.

## محدودیت‌های شناخته‌شده

- مرورگر واقعی روی دستگاه نیست؛ پیش‌نمایش با fetch واقعی HTTP (۲۰۰ و بازگشت محتوای یکسان با فایل) اعتبارسنجی می‌شود.
- مدل رایگان احتمال‌محور است؛ چرخه اصلاح ۳ دور + دستور مینیمال‌سازی دارد، اما در موارد نادر ممکن است بعد از ۳ دور خطا باقی بماند (نسخه پشتیبان قابل بازیابی است).
