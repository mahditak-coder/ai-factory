# قالب Full-Stack پایتون — `fullstack-python` (v0.4.0)

یک قالب استاندارد، اجراپذیر و امن برای پروژه‌های «فول‌استک پایتون + SQLite»
روی Termux — بدون Docker، بدون وابستگی خارجی (فقط کتابخانه استاندارد پایتون).

## ساختار قالب (`core/fullstack_template/`)

```
server.py            نقطه ورود بک‌اند (http.server، فقط 127.0.0.1، پورت از AI_FACTORY_PORT/PORT)
app/db.py            SQLite — اتصال، اسکیمای جداول (users/sessions/customers)، init_db
app/auth.py          PBKDF2-HMAC-SHA256 (100k دور + salt)، نشست‌ها، نقش‌ها
app/api.py           مسیرهای JSON، اعتبارسنجی، CSRF، کنترل نقش، CRUD
ui/index.html        ورود/ثبت‌نام
ui/user.html         داشبورد کاربر (CRUD مشتری‌ها)
ui/admin.html        پنل مدیر (آمار + کاربران + همه رکوردها)
ui/app.js, ui/style.css
tests/test_api.py    ۱۸ سناریوی واقعی (سرور واقعی + DB ایزوله)
config.json, requirements.txt (خالی — فقط کتابخانه استاندارد), README.md
```

## دو مسیر تولید

1. **اسکفولد (قطعی و سریع):** ساخت پروژه با نوع `fullstack-python` از پنل
   → قالب فوراً در `projects/<name>/` کپی و جای‌گذاری (`{{APP_TITLE}}`) می‌شود.
2. **مدل‌محور:** درخواست کاربر + چرخه کارخانه؛ الزامات فول‌استک به‌صورت
   `FS_REQUIREMENT` در دستور مدل تزریق می‌شود (باگ‌ها با checker/fix اصلاح می‌شوند).

## اجرا و پیش‌نمایش

- از پنل: زبانه «اجرا» در `factory.html` → آدرس پیش‌نمایش (`http://127.0.0.1:<port>`)
- دستی: `cd projects/<name> && python server.py`

## اولین کاربر = مدیر

اولین کاربری که در دیتابیس ثبت‌نام می‌کند نقش `admin` می‌گیرد (الگوی
پیش‌نمایش محلی؛ هیچ رمز پیش‌فرضی در کد نیست). کاربران بعدی نقش `user` دارند.

## مدل امنیت (پیاده‌سازی واقعی، نه صرفاً مستند)

| تهدید | پاسخ |
|---|---|
| رمز خام در DB | PBKDF2-HMAC-SHA256 با ۱۰۰٬۰۰۰ دور + salt تصادفی برای هر کاربر |
| SQL Injection | تمام کوئری‌ها پارامتری (`?` placeholders) |
| CSRF | double-submit cookie: کوکی `af_csrf` (خوانا برای JS) + هدر `X-CSRF-Token`؛ توکن از `GET /api/csrf` |
| سرقت نشست | توکن تصادفی ۳۲ بایتی؛ در DB فقط SHA-256 هش‌شده؛ کوکی `HttpOnly; SameSite=Lax; Max-Age=24h` |
| دسترسی عمودی/افقی | مسیرهای مدیریتی در هر درخواست چک می‌شوند (403 برای نقش user)؛ کاربر فقط رکوردهای خودش را می‌بیند |
| نشت اطلاعات | خطاها فقط پیام فارسی امن؛ هیچ اظنایت داخلی در پاسخ نیست |

## آزمون‌ها

```bash
cd projects/<name> && python tests/test_api.py   # ۱۸ سناریو (شامل دوام داده پس از ری‌استارت)
```
یا از پنل: دکمه «🧪 اجرای آزمون‌های پروژه» (`POST /api/factory/testrun`).

مجموعه پذیرش سطح کارخانه: `bash scripts/ai-factory-test-fullstack`
(۲۵ بررسی واقعی: اسکفولد، اجرا، DB، ثبت‌نام/ورود/پنل مدیر، CRUD، دوام داده،
CSRF، اعتبارسنجی، ZIP و محرمانه‌ها، دو پروژه هم‌زمان، توقف صحیح).

## نصب وابستگی‌ها

پروژه‌های حاصل از این قالب **هیچ وابستگی خارجی ندارند** — `requirements.txt`
عمداً خالی است. اگر توسعه بعدی وابستگی خواست، آن را در `requirements.txt`
با نسخه ثبت کنید و از پنل دکمه «📦 نصب وابستگی‌ها» را بزنید
(`pip install -r`، بدون shell). خطایابی نصب در Termux: ابتدا
`pip install --upgrade pip`؛ در خطای کامپایل، `pkg install clang python-dev`.

## رفع خطاهای متداول Termux

- **پنل پاسخ نمی‌دهد:** `bash scripts/ai-factory-status`؛ در صورت توقف،
  `bash scripts/ai-factory-stop && bash scripts/ai-factory-start`.
- **پورت پس از هر اجرا عوض می‌شود:** runner پورت آزاد را دینامیک انتخاب
  می‌کند؛ آدرس پیش‌نمایش را از زبانه «اجرا» یا پاسخ `/api/factory/run` ببینید.
- **خطای زمان اجرای پروژه:** لاگ در `logs/runs/<project>.log`.
- **`__pycache__` کنار قالب:** هنگام import مستقیم ساخته می‌شود؛ اسکفولد آن
  را کپی نمی‌کند و داخل ZIP نیز قرار نمی‌گیرد.

## ماژول هوش مصنوعی مستقل (P2، اختیاری)

`core/aimodule_template/` — ماژول استاندارد `app/aiclient.py`، عمداً **مستقل کامل**
(stdlib-only، بدون OpenCode و بدون AI Factory) که فقط با `scaffold_ai_module`
به‌دست پروژه‌های AI‌دار نصب می‌شود (`ai-tool` از پنل خودکار دریافت می‌کند؛
انواع دیگر چیزی اضافه نمی‌گیرند). تنظیمات: `AI_PROVIDER/AI_BASE_URL/
AI_MODEL/AI_API_KEY(env)/AI_API_KEY_FILE` یا بخش `ai` در `config.json`
(نمونه: `ai.example.json`، بدون هرگونه کلید). ارائه‌دهنده پیش‌فرض: هر سرویس
سازگار OpenAI. ارائه‌دهنده‌های جدید فقط با `register_provider`. کلید فقط
سمت سرور خوانده می‌شود و در پاسخ/لاگ/STANZAS نمی‌آید. خودآزمون ماژول:
`python3 tests/test_aiclient.py` (۱۲ سناریو با سرویس محلی ساختگی).
نقطه توسعه P3: `describe_settings()/apply_settings()` (بدون UI در این نسخه).

## محدودیت‌های واقعی (صریح)

- **فقط پیش‌نمایش محلی:** سرور تنها روی `127.0.0.1` پاسخ می‌دهد؛ برای
  انتشار عمومی، TLS و reverse proxy و rate-limit لازم است که خارج از
  محدوده قالب است (باید به‌تنهایی برپا شود).
- تغییر نقش کاربر با رابط کاربری ارائه نشده (فقط اولین کاربر = admin).
- SQLite با WAL برای هم‌زمانی سنگین عالی نیست؛ مناسب محیط پیش‌نمایش است.
- در مسیر مدل‌محور، رفتار مدل آزاد می‌تواند نوسانی باشد؛ چرخه checker/fix
  ضریب اطمینان را بالا می‌برد اما صددرصد قطعی نیست.
