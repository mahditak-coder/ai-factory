# {{APP_TITLE}} — برنامه Full-Stack مدیریت مشتریان

بک‌اند پایتون (فقط کتابخانه استاندارد) + SQLite + رابط HTML/JS — بدون Docker، مخصوص Termux/اندروید.

## اجرا

```bash
python server.py
# پورت از env AI_FACTORY_PORT/PORT (پیش‌فرض 8770)
# میزبان از env AI_FACTORY_HOST/HOST (پیش‌فرض امن 127.0.0.1)
# نمونه شبکه‌ای:  AI_FACTORY_HOST=0.0.0.0 AI_FACTORY_PORT=9000 python server.py
```

## وابستگی‌ها

هیچ‌کدام — کد فقط از کتابخانه استاندارد پایتون استفاده می‌کند.
`requirements.txt` خالی است؛ اگر نسخه‌های بعدی وابستگی خارجی بخواهند،
در Termux با `pip install -r requirements.txt` نصب شوند.

## اولین کاربر = مدیر

اولین کاربری که در این پایگاه داده ثبت‌نام می‌کند نقش `admin` می‌گیرد؛
کاربران بعدی `user` هستند. هیچ رمز پیش‌فرضی در کد نیست.

## پایگاه داده

- مسیر: `data/app.db` (بار اول ساخته می‌شود)
- داده‌ها پس از توقف/اجرای مجدد برنامه باقی می‌مانند (تست‌شده در `tests/test_api.py`).

## امنیت

- رمزها با **PBKDF2-HMAC-SHA256 (100k دور + salt تصادفی)** هش می‌شوند — ذخیره خام ممنوع.
- کوئری‌های SQL همگی **پارامتری** (ضد SQL Injection).
- نشست با کوکی HttpOnly/SameSite=Lax و توکن تصادفی ۳۲ بایتی (هش‌شده در DB).
- درخواست‌های تغییردهنده (POST/DELETE) نیازمند **CSRF double-submit token**.
- مسیرهای مدیر در سرور با نقش چک می‌شوند: کاربر عادی → **403**.
- خطاها فقط پیام فارسی امن برمی‌گردانند؛ هیچ اطلاع داخلی/محرمانه‌ای افشا نمی‌شود.

## آزمون‌ها

```bash
python tests/test_api.py
```

۱۸ سناریوی واقعی شامل ثبت‌نام/ورود/خروج، نقش‌ها، محافظت مدیر، CRUD واقعی،
CSRF، اعتبارسنجی، دوام داده پس از ری‌استارت و سلامت صفحات.

## استقرار به‌عنوان سرویس مستقل

- **محلی (پیش‌فرض):** سرور فقط روی `127.0.0.1` گوش می‌دهد؛ آدرس `http://127.0.0.1:8770`.
- **شبکه محلی:** `AI_FACTORY_HOST=0.0.0.0 AI_FACTORY_PORT=9000 python server.py`
  و دسترسی با IP دستگاه (مثلاً `http://192.168.x.x:9000`).
  ⚠️ با این حال *همه* صفحات (از جمله `admin.html`) روی شبکه باز می‌شوند —
  برای انتشار واقعی، همان‌طور که پایین آمده، از Reverse Proxy استفاده کنید.
- **تفکیک محیط‌ها:** هر نمونه فقط از متغیرهای محیطی همین فرایند می‌خواند؛
  با پورت و دیتابیس جدا (`AF_DB_DIR`) چند محیط مستقل (توسعه/آزمون/دمو)
  هم‌زمان می‌توانند اجرا شوند. هیچ ورود توسعه‌ای پیش‌فرض وجود ندارد.
- **رمزها و کلیدها:** هیچ کلیدی در کد یا HTML/JS نیست؛ فقط از متغیر محیطی
  یا فایل خصوصی (اجازه `0600`) خوانده می‌شود. هرگز در لاگ یا پاسخ API نمی‌آید.
- **HTTPS:** خود سرور TLS ندارد. برای انتشار عمومی، سرور را روی `127.0.0.1`
  نگه دارید و پشت Reverse Proxy با گواهی TLS قرار دهید. مثال nginx:

```nginx
server {
    listen 443 ssl;                       # گواهی: certbot/Caddy مدیریت می‌کند
    ssl_certificate     /etc/letsencrypt/live/your.domain/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your.domain/privkey.pem;
    location / {
        proxy_pass         http://127.0.0.1:8770;
        proxy_set_header   Host $host;
        proxy_set_header   X-Forwarded-For $remote_addr;
        proxy_set_header   X-Forwarded-Proto https;
    }
}
```

  یا با Caddy (TLS خودکار): `your.domain { reverse_proxy 127.0.0.1:8770 }`
